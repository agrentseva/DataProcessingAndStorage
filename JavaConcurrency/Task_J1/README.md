### Микросервис, генерирующий пары ключей RSA по запросам клиентов.

#### Задачи сервера: 
1. Сервис должен **слушать на сокете TCP** так, чтобы к нему можно было подключаться с других компьютеров. Клиенты подключаются и передают имя *(текстовую строку ASCII)*, заканчивающуюся **нулевым байтом**.
2. Если имя было получено первый раз, сервер **генерирует пару приватного и публичного ключей RSA** c 8192-битным приватным ключом и **выдает сертификат X509 на публичный ключ и имя, переданное клиентом**. 
3. Затем он **сохраняет имя и ключи в своей оперативной памяти** и **передает полученную пару ключей** клиенту.
4. Если имя ранее уже запрашивалось, сервер отдает **ранее** созданную пару ключей и сертификат.

**Повторный запрос с тем же именем может прийти раньше, чем генерация и подпись ключа завершится.**

#### Задачи клиента:
1. Получает *имя, адрес или DNS имя сервера и номер порта*, **присоединяется к серверу** и **сохраняет полученную пару ключей в виде .key и .crt файлов.**
2. Клиент обязан иметь опции 
	1. **командной строки**, позволяющие **задать задержку в секундах** между отправкой запроса и считыванием ответа *(имитация медленного клиента)*, 
	2. **завершение вместо считывания ответа** *(имитация аварийного завершения клиента).*

#### Генерация ключей:
1. Должна быть реализована с **использованием фиксированного пула нитей**, предположительно (но необязательно) по числу процессорных ядер вашего компьютера.
2. Количество генерирующих нитей **должно задаваться в командной строке** при запуске.

--- 
#### Техническая часть:
1. Для **генерации пар ключей** следует использовать *java.security.KeyPairGenerator*, для подписи публичного ключа *org.bouncycastle.cert.X509v3CertificateBuilder* (встроенный класс java.security.cert.CertificateFactory обеспечивает чтение сертификатов из файлов, но не их создание).
2. **Ключ для подписи** должен быть **создан заранее и читаться из файла** при запуске микросервиса.
3. **Issuer Name** должен быть **фиксированным** (задаваться из *командной строки* или *конфигурационного файла* микросервиса).
4. **Subject Name** - **совпадать с именем**, который *передает клиент.*
5. Микросервис **содержит нить или несколько нитей**, ответственных за коммуникацию с клиентами.
6. Нити используют **мультиплексирование ввода-вывода** при помощи *java.nio.channels.Selector*, **принимают новые соединения** и **запросы на генерацию ключей,** устанавливают **запросы на генерацию ключей в очередь**, откуда их получают свободные генерирующие нити. 
7. Построив ключи и сертификат, генерирующая нить **ставит запрос на передачу ключа в другую очередь**, откуда их получает передающая нить или нити. Таким образом, **генерирующая нить может быть заблокирована, только если нет работы**, но **не на передаче результата** клиентам.
8. Сервер должен **поддерживать не менее сотни одновременно активных клиентов** (включая “медленные” клиенты), поэтому **создавать нить ОС на каждое** клиентское соединение **недопустимо**.

---
#### Команды для терминала: 
1. **Генерация ключа подписи:**

`openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out signing-key.pem`

2. **Запуск сервера:**

`./gradlew server --args='8080 4 "CN=KeyServer" signing-key.pem'`

3. **Тесты:**

`./gradlew client --args='SimpleTest localhost 8080'`
   
`./gradlew client --args='DelayTest localhost 8080 --delay 30'`

`./gradlew client --args='AbortTest localhost 8080 --abort'`
 
`./gradlew client --args='GenerationTest localhost 8080 --delay 30'`

`./gradlew client --args='GenerationTest localhost 8080'`

`./gradlew client --args='Met localhost 8080'`
